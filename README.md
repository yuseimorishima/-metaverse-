# NEON TAG — 連打で、逃げきれ。

最大5人で遊べる、ブラウザ向け3Dマルチプレイ鬼ごっこ。**GitHub Pagesを開くだけで参加できます。Renderの登録やサーバーURLの入力は不要です。**

## 一人称の学校探索（試作）

「ひとりで学校を探検」から、通信サービスへの接続なしで校舎内を歩けます。目線の高さは1.65m。WASDで移動、画面のドラッグで見回し、PCでは「見回す」でマウスを固定します（Escで解除）。Q/Eキーでも左右を向けます。スマホでは左下の方向パッドで移動し、画面の右側をスワイプして見回します。スペース/TAPの連打加速も残しています。

スポーン地点に校内マップと操作説明の案内板があります。画面に固定する案内文・現在地・ミニマップは表示しません。ルームコード、参加者一覧、鬼ごっこ開始、画質・音の設定、退出は右上のメニューにまとめています。壁・机・本棚・案内板の当たり判定があります。廊下・部屋の出入口・校庭への動線を検証済みです。スポーン地点には1〜5階の案内、各階の階段付近には階数と部屋名の案内板があります。画面に固定した階数表示はありません。

東京学芸大学附属竹早中学校の[公式校舎案内](https://www2.u-gakugei.ac.jp/~takechu/building-info)と部屋・施設の写真を参考に、L字の複数階の外観、1階の相談室・国語室・SUGOI部屋・音楽室・技術室・用務員室、体育館、ピロティー、人工芝の下校庭を制作しています。廊下は幅3.4mにそろえ、通路のつながりと出入口を整理しました。実際の寸法・部屋順・扉や体育館の位置は近似です。食堂は設けていません。1〜5階と屋上・屋外を探索できます。校舎正面の右側にある階段で、踊り場を折り返しながら上り下りします。階段の位置・形・寸法も近似です。[参照資料と再現範囲](references/takehaya-school.md)に根拠と近似した部分を記載しています。

探索のブラウザ検証：`npm run test:school`。外部通信をブロックした状態で、ソロ開始・一人称移動・廊下の端から端までの移動・体育館・下校庭・1〜5階への階段移動・下り階段・目線の高さ・各階の案内板・退出・スマホ表示と、全階の描画上の扉と衝突判定の一致を確認します。

## 追加した上階

- 2F：事務室、リソースルーム、保健体育室、被服室、保健室、調理室、1学年教室、職員室、共用学習スペース。
- 3F：物理化学室、科学実験室、生物地学室、Dルーム、2学年教室、西側のメディアセンター。
- 4F：英語室、美術室、グループ学習室、社会科室、視聴覚室、3学年教室、共用ラウンジ。
- 5F：実習生室、会議室、屋上テラス。

階の割り当ては公式案内を参照しています。共用スペース、部屋順、家具、階段やメディアセンターへの動線はゲーム用の近似です。実験台・流し台・調理台・ミシン台・ベッド・本棚・机・投影設備などを部屋に合わせて配置しています。食堂は追加していません。

ホストが高さを含む移動を管理し、他のプレイヤーの高さも同期します。上階でも連打ダッシュと鬼ごっこができます。階段は歩くだけで上り下りでき、ジャンプや階選択ボタンは使いません。床のない場所や屋上の柵の外へ進めず、違う階にいる相手を真上・真下からタッチすることもできません。ラウンド開始時は全員が1階のスポーン地点に戻ります。

## 遊び方

1. ページを開いて「ONLINE」になるまで待ち、名前を入力して「ルームをつくる」。
2. 友達も同じページを開き、ホストに教えてもらった6文字のコードを入力して参加。
3. 2〜5人集まったらホストが右上のメニューからスタート。
4. WASD / 矢印キーで移動、**Spaceを連打**すると加速。スマホは方向パッドとTAPボタンを使います。
5. 光るリングが鬼。触れた相手に鬼が交代し、3秒間は再タッチできません。
6. 2分間で、鬼でなかった時間を競います。終了後は同じルームで再戦できます。

**部屋を作った人のブラウザがゲームを管理します。ホストは対戦中、ページを閉じたりバックグラウンドに移したりせず、開いたままにしてください。ホストが切断すると部屋は終了します。**

## グラフィック

壁・床には実寸に対応した木目、塗装、タイルの質感を設定し、窓は透過と反射を使っています。机・椅子・本棚・窓枠・照明器具を個別の部品で描画し、日光の影と接地影、空の環境光を加えています。公式写真を参考に、SUGOI部屋の白い机と青・黄のカーペット、音楽室の木床・丸椅子・ピアノ、技術室の作業台と万力、体育館の舞台と緑の幕を加えています。実測に基づく正確な復元ではありません。写真自体は転載していません。食堂は追加していません。

メニュー内（入口画面では右上）の「画質：標準」を押すと「画質：軽量」になり、動的な影・室内の補助光・描画解像度を軽くできます。設定はブラウザに保存されます。入口画面が静止した後は再描画を止めて負荷を抑えます。ブラウザテストでは標準画質の描画を確認し、ソフトウェア描画環境での歩行・通信は軽量モードで検証します。標準ではモバイル用に影の解像度を抑えています。材質や空のテクスチャはすべてローカル生成で、外部画像CDNやAPIキーを必要としません。

## 公開方法

生成済みの `docs/` を同梱しています。GitHub Pagesの **Deploy from a branch → main → /docs**、または **main → / (root)** に対応しています。ルートからは `docs/` へ転送します。

GitHub上で `public/` を編集して自動反映したい場合は、**Settings → Pages → Source → GitHub Actions** を選んでください。`main` 更新時に `.github/workflows/pages.yml` がテスト・ビルド・公開します。公開アドレスのルートと、既存の `/docs/` の両方に対応しています。

**通常は `BACKEND_URL` を設定しません。** 設定すると従来の外部WebSocketサーバーモードへ切り替わります。ブラウザ間通信を使う場合は、このリポジトリ変数を空にして再デプロイしてください。

## 通信方式と制限

- PeerJS / WebRTCでホストと各プレイヤーを接続。ホストが移動・加速・接触・得点を30Hzで判定します。
- 接続仲介にはPeerJS Cloudの公開サービスを使用。ライブラリ標準のSTUN / TURN設定を使用します。外部サービスなので可用性を保証するものではありません。
- ゲームの描画ライブラリと通信ライブラリは同梱し、外部CDNからのスクリプト読み込みは不要です。プレイヤーの名前やゲーム状態は接続した相手と共有されます。
- 学校・会社などの通信制限の強いネットワークではWebRTCや仲介サービスへの接続が拒否される場合があります。つながらない場合は別のWi-Fiやモバイル回線で試してください。
- 切断後の自動復帰、ホスト移譲、永続アカウントはブラウザ間モードにはありません。新しいルームを作成してください。
- 友達同士での利用を想定しています。ホストに対する不正対策やVRヘッドセット操作は未実装です。

## ローカル開発

Node.js 22以上（検証環境24.19.0）。

```sh
npm ci --cache /tmp/neon-tag-npm
npm test
npm run build
```

`npm run build` はPages用ファイルを `docs/` に生成し、Actions用の `_site/` にルート・`docs/` 両方の配置を作ります。生成した `docs/` はコミットし、`_site/` はコミットしません。

ブラウザ間モードのローカル確認：`python3 -m http.server 4173` を実行し、配信された `docs/` をブラウザで開きます。接続仲介サービスへのインターネット接続が必要です。

任意のNode.jsサーバーモードも残しています：`npm start` で `0.0.0.0:3000`、`PORT=8080 npm start` でポート変更。開発中のサーバー監視は `npm run dev`。このモードは同じサーバーでページとWebSocketを提供し、ホスト退出時に別プレイヤーへホストを移譲できます。

## ブラウザテスト

```sh
npx playwright install chromium
npm run test:browser
```

既存のChromiumを使う場合：`CHROMIUM_PATH=/usr/bin/chromium npm run test:browser`。

このテストはローカルの仲介サーバーを立ち上げ、実際のRTCDataChannelで5人参加、6人目の拒否、開始、連打加速、上階の高さ・アバター位置の同期、ホスト切断を検証します。ゲーム用のNodeサーバーは使いません。管理されたブラウザで直接UDPが禁止されている場合は、ローカルTURNのTCPリレーを使います。`TEST_TURN_URL`（例：`turn:127.0.0.1:34780?transport=tcp`）、`TEST_TURN_USER`、`TEST_TURN_PASSWORD` でテスト用リレーを指定できます。今回のブラウザ検証はこのローカルTCPリレー経由で実施しています。公開PeerJS Cloud・外部ネットワークへの到達性は、この環境のアクセス制限で未確認です。

`npm test` はサーバーモード経由で共通ゲームルール（5人制限、移動、障害物、鬼交代、得点、終了）を検証します。

## 編集するファイル
