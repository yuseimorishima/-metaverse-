# NEON TAG — 連打で、逃げきれ。

最大5人で遊べる、ブラウザ向け3Dマルチプレイ鬼ごっこ。Three.js と Node.js / WebSocket で動きます。

## 起動

Node.js 22以上（検証環境: 24.19.0）。

```sh
npm ci --cache /tmp/neon-tag-npm
npm start
```

サーバーは `0.0.0.0:3000` で待ち受けます。ポート変更は `PORT=8080 npm start`。
開発中のサーバー自動再起動は `npm run dev`、ブラウザ側は変更後リロードしてください。ビルド処理は不要です。

## 遊び方

1. 名前を入力して「ルームをつくる」。
2. 友達が**同じサーバーのページ**を開き、6文字のルームコードを入力して参加。`?room=コード` 付きのURLでも入力を補完できます。
3. 2〜5人集まったらホストがスタート。開始前も自由に移動できます。
4. **WASD / 矢印キー**で移動、**Spaceを連打**すると加速。押しっぱなしでは加速しません。スマホでは方向パッドを押しながら TAP ボタンを連打できます。
5. 光るリングが鬼。鬼が誰かに触れると交代。開始直後は4秒、交代後は3秒のタッチ待機があります。
6. 2分間、鬼でなかった合計時間を競います。終了後に同じルームで再戦できます。

ルームコードの横のボタンでコードをコピーできます。効果音は右上の「音 OFF」で有効にできます。

## マルチプレイの公開

開発サーバーだけでは離れた友達への公開は完了しません。全員がアクセスできる1台のNode.jsホストで起動し、HTTPSとWebSocket Upgrade対応のリバースプロキシを接続してください。同一LANならホストのLANアドレスでも接続できます。クライアントはページと同じホストの `/` にWebSocket接続します。HTTPSの場合は自動でWSSを使用します。静的ホスティング単独では動きません。

状態は単一サーバーのメモリ内にあり、再起動するとルーム・スコアが消えます。複数プロセスへの分散や永続アカウント、切断後の自動復帰は未実装です。切断時はホストを引き継ぎ、1人になるとラウンドを終了します。対戦途中の参加はできません。

外部CDN・APIキー・データベースは不要です。WebGLが必要です。これは画面で遊ぶ3Dゲームで、VRヘッドセット操作には対応していません。

## 検証

```sh
npm test
```

HTTP配信、5人参加と満員制限、ホスト権限、対戦途中の参加拒否、単独開始拒否、同一オリジン制限、サーバー側の移動上限・障害物・加速と減衰、タッチ交代と猶予、終了・スコア・ホスト移譲をテストします。

サーバーが移動・加速・接触・得点を30Hzで判定し、ブラウザは座標を補間します。入力正規化・タップ頻度制限・メッセージサイズ/頻度制限があります。認証や高度な不正対策はなく、友達同士での利用を想定しています。

## GitHub Pagesで公開する

このリポジトリは **GitHub Pages（ゲーム画面）＋ Render（マルチプレイ通信）** に対応しています。Pagesだけではルーム作成や対戦は動きません。

### 1. Renderで通信サーバーを公開

1. Renderにログインし、**New → Blueprint** からこのGitHubリポジトリを選択します。
2. ルートの `render.yaml` が認識されます。内容・料金を確認して作成します。設定はfreeプランですが、利用条件はRender画面で確認してください。
3. デプロイが完了したら、表示された `https://…onrender.com` を控えます。このURLでゲーム本体も直接遊べます。
4. `https://…onrender.com/health` が `{"ok":true}` を返すことを確認します。

`ALLOWED_ORIGINS` は `https://yuseimorishima.github.io` を許可済みです。別アカウントや独自ドメインのPagesを使う場合はRenderのEnvironmentで正確なオリジン（パスなし）を設定してください。複数はカンマ区切りです。無料インスタンスの休止・再起動では接続が切れ、ルームは消えます。

### 2. Pagesの接続先を設定

GitHubリポジトリの **Settings → Secrets and variables → Actions → Variables** で、リポジトリ変数 `BACKEND_URL` にRenderのHTTPS URLを追加します。これは公開URLであり、Secretではありません。

### 3. ゲーム画面を公開

**Settings → Pages → Build and deployment → Source** を **GitHub Actions** にします。**Actions → Deploy NEON TAG to GitHub Pages → Run workflow** を実行してください。以降は `main` の更新時にテスト・ビルド・公開が自動実行されます。公開されたURLはActionsのdeployジョブまたはSettings → Pagesで確認できます。

公開後は、友達全員がそのページを開くだけで同じRenderサーバーにつながります。`BACKEND_URL` が未設定でも画面は表示され、「接続先を設定」にRender URLを入力して接続できます。この手動設定は各ブラウザに保存されるため、全員の初期設定を省くにはリポジトリ変数を設定して再デプロイしてください。

すでに **Deploy from a branch** を設定している場合も、`main` の `/ (root)` または `/docs` から表示できます。ルートの `index.html` は `docs/` へ転送します。ただし、GitHub上で `public/` を編集した内容を毎回自動反映するにはGitHub Actions方式を選んでください。

### ファイルの編集

- 画面・見た目・操作：`public/index.html`、`public/style.css`、`public/app.js`
- ゲームルール・人数・判定：`server.js`
- Render：`render.yaml`
- 自動公開：`.github/workflows/pages.yml`
- `docs/` は `npm run build` で作る生成物です。直接編集せず、元の `public/` を編集してください。

`npm run build` はThree.jsも含めた静的ファイルを `docs/` に出力します。生成物をコミットする場合、更新後にこのコマンドを実行してください。ビルドに外部CDNや秘密情報は必要ありません。
